## 1. Concise Diagnosis of Original Defects

Our deep inspection identified **three primary root causes** that caused the distorted, detached, and blob-like visual defects in the original implementation:

### Defect 1: Z-Axis Inversion Between Three.js Extruded Shapes and World Coordinates
* **The Root Cause:** In `Scene3D.tsx`, Three.js shapes were constructed using `s.moveTo(cadX - ORIGIN_X, -(cadY - ORIGIN_Y))`. When the mesh was rotated by `[-Math.PI / 2, 0, 0]` to orient it horizontally, a 2D shape vertex $(sx, sy)$ is transformed by the rotation matrix into 3D space as $(sx, 0, -sy)$.
* **The Mathematical Inversion:** Since $sy$ was negated during construction ($sy = -(cadY - ORIGIN_Y)$), its 3D world position became $-sy = -(-(cadY - ORIGIN_Y)) = +(cadY - ORIGIN_Y)$.
* **The Detachment:** Simultaneously, the outer site boundary (`4E35`), text centroids, and road points were transformed directly in world space using `-(cadY - ORIGIN_Y)`. 
* **The Visual Impact:** The extruded plot meshes were inverted along the Z-axis (mirrored North-to-South) relative to the outer perimeter boundary line and text markers. This caused the boundary to appear completely detached from the parcels.

### Defect 2: Polygon Assignment Scrambling via Catalog Index Lookup
* **The Root Cause:** In `prepare_prototype_data.py`, `plots.json` was generated by looking up polygon IDs (`POLY_0042`, etc.) in a newly re-polygonized catalog whose line-order differed from `reconciliation.json`.
* **The Visual Impact:** Plots were assigned polygons hundreds of meters away from their actual CAD ellipse markers (e.g., Plot 338 at $X=10603$ was rendered inside a polygon at $X=10123$).

### Defect 3: Compound Block Duplication & Missing Parcel Boundary Strokes
* **The Root Cause:** Multiple plots belonging to compound blocks (e.g., Plots 471–479 in CAD Block 1) each rendered a duplicate instance of the entire unpartitioned compound polygon. Adjacent plots had no border/stroke geometry, causing touching green meshes to merge into undifferentiated masses. Roads were rendered as a single flat generic plane ($1400 \times 600\text{ m}$) under everything.

## 2. Corrective Architecture & Implementation

### 2.1 Direct Spatial Containment Pipeline (`build_clean_geometry.py`)
* Replaced catalog ID index lookup with rigorous GEOS point-in-polygon containment:
  $$\text{polygon.buffer}(0.05).\text{contains}(\text{Point}(\text{markerX}, \text{markerY}))$$
* Snapped all linear CAD lines and arcs (`WALL`, `DIM`, `0`, `4E35`) using a 5mm grid precision node (`shapely.set_precision(..., grid_size=0.005)`).
* Identified all 22 compound blocks and deduplicated them.
* Classified all 7 incomplete boundary plots (Plots 176, 189, 196, 262, 355, 356, 464) without fabricating fake polygons.

### 2.2 Canonical Coordinate System & Origin
* **Bounding Box:** $X \in [10123.51, 10803.19]$, $Y \in [-1585.36, -1259.52]$ (Width = $679.68\text{ m}$, Depth = $325.84\text{ m}$).
* **3D Scene Origin:**
  $$\text{SITE\_CENTER\_X} = 10463.35, \quad \text{SITE\_CENTER\_Y} = -1422.44$$
* **Canonical World Mapping:**
  $$X_{3D} = cadX - 10463.35, \quad Z_{3D} = -(cadY - (-1422.44))$$
* **Three.js Shape Construction:**
  $$s.moveTo(cadX - 10463.35, cadY - (-1422.44))$$
  Upon `[-Math.PI / 2, 0, 0]` rotation, $Z_{world} = -sy = -(cadY - \text{SITE\_CENTER\_Y})$, aligning identically with the world perimeter, roads, labels, and beacons.

## 7. Remaining Geometry Limitations

1. **Seven Incomplete Boundaries (Plots 176, 189, 196, 262, 355, 356, 464):**
   - In the reference CAD file (`SUB-KESNAND-13.11.2025.dxf`), these plots lie along the perimeter boundary wall where drafting gaps of 0.2m–0.8m exist in the `WALL` layer.
   - *Treatment in Platform:* Rendered with 3D warning beacon pins at their known CAD marker coordinates. They are not fabricated into artificial rectangles, preserving CAD truth.
2. **Compound Blocks (73 plots across 22 blocks):**
   - In the source CAD, these areas (such as Block #471–479) were drafted as single large parcel envelopes without internal dividing line segments in the `WALL` layer.
   - *Treatment in Platform:* Rendered once as compound block envelopes with clear warning badges and the Subdivide Compound Block manual workflow in the 2D Audit view.
